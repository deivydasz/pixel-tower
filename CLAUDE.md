# Pixel Tower

Player-facing name: **Idle Pixel Tower** (matches the live URL; used for the page title and home screen). The repo stays `pixel-tower`.

A very simple single-tower defence game in pixel style, for web and mobile browsers.
The whole game is one file: `index.html` (HTML + CSS + vanilla JavaScript, Canvas 2D). No build step, no dependencies.

## Game design (decided)
- One tower in the middle of the screen. Enemies attack from all sides.
- Enemies: Grunt (basic), Runner (fast, from wave 3), Tank (slow, tough, from wave 5).
- Killed enemies burst into pixels that fly to the tower. Pixels are the in-run currency.
- Blast fires only from the BLAST button (or Space on a keyboard), never from tapping the play area; tapping the play area only resumes from pause.
- Player-facing names: the screen-wide ability is **Blast** (code still calls it `nova`), the armor upgrade is **Dmg sponge** (code key `armor`).
- In-run upgrades (cost pixels): six stats. Damage and Tower HP from the start; Fire rate (wave 5), Range (8), Dmg sponge (12, flat armor per hit), Pixel magnet (16, more pixels per kill), Pixel bank (20, interest on unspent pixels at each wave clear, capped per level) unlock by best wave, mid-run too. Healing upgrades were tried and made the tower immortal in simulations, so avoid them.
- Layout: HUD, game screen, tabs and upgrades share one width (page width, max 540px). The game screen is always 180 game px wide and its height adapts (200-300 game px, `H`/`CY` are variables) to fill the space; thin 2px edge. The HUD has no best-wave number during runs, only a gold "New best!" after passing it.
- In-run upgrade grid uses tabs (`cat` in `UP`: atk Power, def Survival, eco Economy), fixed at two rows tall so the game screen never moves; a dot marks a tab with an affordable upgrade.
- The battlefield zooms out (down to 0.5) when Range would leave the screen; enemies then spawn just off the visible edge. HUD, banners, labels and the cat are not zoomed.
- Run-only late upgrades (`run:1` in `UP`, not in the Foundry): Heavy rounds (wave 30 in the current run; hits knock Tanks back) and Crit power (wave 35 in the current run, needs Critical bits; crit multiplier x3 +0.5/level). Locked at the start of every run.
- Each cleared wave gives pixels and pixel chips. Chips are the between-runs currency.
- Pixel foundry: spend chips on permanent upgrades to the same six skills (same unlocks). Saved in localStorage.
- Game over menu: header and reason, an "Unlocked this run" card (new upgrades, bosses, cores, Bit Theory, research now available or finished; hidden if nothing new), run stats, Play again, next-unlock goal, then Foundry · Bit Theory · Main menu. Bit Theory is highlighted with "New!" when the run unlocked something for it. No suggested-upgrade buttons (removed 2026-11-04, the user wants players to visit the Foundry): the Foundry button on game over and home is highlighted (gold, pulsing, "Upgrade ready!") when the chips buy something (`fyReady()`, `fyTile()`).
- Waves keep getting stronger: count +2 per wave, HP x1.11 per wave, damage +10% every 5 waves (`EN` in index.html; minK can floor what Dmg sponge blocks, unused). Bosses keep their own numbers. Chosen 2026-11-02 from campaign sims (`tests/campaign.sim.js`); before that damage never grew and HP was x1.12.
- Certificates (not "milestones"): first completion of wave 10, 20, 30... earns a certificate (banner "CERTIFICATE: name / Collect it on the menu"); its one-time chips (and the skin set at 30/50/70) are paid only when collected by tapping it on the Certificates screen, lowest first (`claimCert()`, saved as `claim`, v13; older saves count as collected). The menu button says "Reward ready!". Chips: `certChips(w)=w*(1+w/20)/2` (about a third of a run to that wave; ~5% of all chips in sims, doesn't speed up progress). Names in `CERT_NAMES`; saved as `cert`. Screen from the home menu.
- Idle income (`IDLE`, `idleCheck()`): unlocks after the first finished run (was the first boss until 2026-11-04; moved so day-one players have a reason to return). Time away (game closed, or hidden outside a run; hidden runs never pay) up to 4h pays `runChips(best)` chips per 4h and a starting-pixel stash of 10 px per best wave (cap one 4h batch), spent by `useStash()` when a run starts. Saved as `seen` and `stash` (v11). Under 5 min pays nothing. Preview shortcut `?away=MIN`.
- Boss attempts: a run ending with a boss alive pays `bossChips*share of HP taken` (no core); game over shows "Brute had 35% HP left". Game over also shows one "so close" line (`nearMiss()`).
- First ever load (no history, best 0) starts a run straight away instead of the menu; the start tip card pauses it until the first tap. The first buy prompt (when Damage is affordable) says "Tap Damage below to hit harder" and the Damage button pulses until bought.
- Home screen before the first run and between runs: Play, a next-unlock goal card, Progress (Foundry, History), Unlocks (Bosses tracker from wave 16, shown as "???" with "Something is waiting for you at wave 16..." until the first boss is met (`bossSeen()`; How to play / Certificates / Bit Theory boss text hidden too); Daily run and Drivers from wave 25; Skins from the wave 30 certificate; the four tiles sit in a 2x2 grid), How to play.
- Effects (`S.fx`, `sparks()`, `ring()`, capped at `FX_MAX`, real time): projectile trails, hit sparks (gold on crits), a ring and sparks when an enemy dies, red debris when the tower is hit, Blast = filled shock ring + debris + soft screen flash, boss arrival = pulsing red screen edges, boss kill = two rings, many sparks, shake and flash. Screen flash, red edges and shake are skipped with reduced motion.
- Menu screens (decided 2026-11-07): most should fit a phone without scrolling (checked at 375x667 and 320x640); the Back button of every menu screen is pinned to the bottom (sticky) so it is always visible.
- Look and skins (`SKINS`, decided 2026-11-02): everything is drawn in code as pixel grids, no image files. Default look is **Classic** (simple one-colour enemy shapes, plain square tower with a barrel, plain background). Certificates at wave 30, 50, 70 each unlock a set (Bug Hunt, Neon, Crystal) of three skins: enemies (+5/10/15% pixels per kill), tower (+3/6/9% damage), background (+5/10/15% pixels and chips per wave clear). Every OWNED skin's bonus counts whatever is worn; the worn look per slot is picked on the Skins screen (saved as `skin` {e,t,b}, v12). Enemy sprites have two walk frames (`ESPR`, `ESPR0/2/3`, palettes in `ESK`), white hit and yellow crit flash, and are a little larger than the hitbox (`t.s`, unchanged). Skinned towers grow with levels bought THIS run (tiers at 1/5/12: HP = bigger base with corner towers and battlements, Damage = longer/thicker barrel, Range = corner antennas, Fire rate = core glow, Pixel magnet = gold rim); Dmg sponge plates show on every tower. Barrels: one per Spray and Pray bullet, fanned, at most 3 (the user's rules: more guns only from Spray and Pray; a 4th bullet makes the middle barrel fat, a 5th the two side ones instead, a 6th all three). Backgrounds are pre-rendered once per screen size (`bgCanvas`). The legend shows the worn enemy sprites.
- Daily run (`DAILY`, `DAILY_MODS`, decided 2026-11-04; unlocks at best wave 25): one challenge per local day, the same for everyone: a fresh tower (`ML`/`RL`/`skinB` return 0 for Foundry, research and skin bonuses when `S.daily`), today's twist (7 in `DAILY_MODS`, shuffled per 7-day block from the date, never twice in a row) and seeded spawns (`drand`). Free retries; reward = chips for today's best wave, paid as it improves (`dailyChips`: half of `runChips(best)` for beating the wave-16 boss (`DAILY.top`=17), linear below; +10%/day streak, max +50%). No normal chips, cores, certificates or best-wave changes; History marks them "Daily". Saved as `daily` (v14). Sims (bosses at 16): fresh-tower bot mostly stops at the wave-16 boss (Rush hour ~15, Glass cannon ~22, Spray day ~32), 5-12 min. Stats event `daily`. Preview shortcut `?twist=1..7`.
- Drivers (code: `BOT`, `BOTS`, `M.bots`; decided 2026-11-07, the user's idea; renamed from Bitbots, the user didn't like "bots"): helper robots in normal runs only (not Daily runs). Unlock at best wave 25 with the Daily run (home tile in Unlocks, screen `#rb`). Paid with **packets** (code `M.nib`; renamed from nibbles): Daily runs pay `dailyNibs` = 10 for beating the wave-16 boss (linear below), +1 per 4 waves after, times the streak bonus, paid as today's best improves (`daily.np`); certificates from wave 30 pay `certNibs` = wave/5 when collected. Building a driver costs 10 and gives Size 1 + Power 1; then Size (field radius 13+1.5*s) and Power level separately up to 10, each upgrade 3+3*lv (`M.bots` {cache,lag,debug: {s,p}}, v15). Each driver flies (45 px/s, kept on screen) to its own target within range+12: Cache Driver follows the tower's target, kills in its field drop +20%+6%/power pixels; Lag Driver goes to the biggest crowd near the tower, every 8-0.4*power s freezes enemies in its field for 1+0.15*power s (bosses half; frozen enemies don't move, hit or spawn; cyan frame and a jitter); Debug Driver follows the toughest enemy in the tower's range (bosses first), shots deal +10%+5%/power damage in its field (green corner marks). Idle drivers orbit the tower. Pause panel lists them; one-time toast tip `bots`; Daily game over has a Drivers shortcut when something is affordable. Stats event `bot` {k, t: b/s/p, s, p, c}. Preview shortcuts `?nib=N` (packets), `?best=N`. Sims 2026-11-07 (before the Size/Power split, one level = both; 16 runs, median best wave; bosses at 32/48 are the walls): Foundry 4: none 32, all Lv5 32, all Lv10 36; Foundry 8: none 39, all Lv1 42, all Lv5 42, all Lv10 44-45. Lag mostly raises the worst runs (min 32 > 36), Cache about +40-60% pixels.
- Glitches (`GLITCH`, `GLITCHES`, decided 2026-11-04; pixel-themed names on purpose, not borrowed from other games): run-only perks. Every wave is a "bit"; 8 cleared bit waves compile into a BYTE (wave 8, 16, 24..., the user's idea; HUD byte meter of 8 bits next to the wave number): the screen glitches (torn colour-split scan lines) and the BYTE! panel offers 3 random glitches (seeded in daily runs); the run waits for the pick (auto-picked while hidden; `GLITCH.auto` in tests/sims). Picking one again stacks it up to its max. Sharp Pixels (+15% dmg), Turbo Bit (+12% rate), Widescreen (+8 range), Anti-Aliasing (-8% enemy hit), Scanlines (+15% HP), Pixel Rain (+20% px per kill), Compression (-8% upgrade cost), Refresh Rate (-20% Blast recharge), Dither Shot (+4% x3 crit), Stray Bit (+1 bullet, max 1, rarer), Save State (survive one killing blow at half HP, rarer). Values in `GLITCHES[k].v`. Sim 2026-11-04 with values about twice these (offers at 5/15/25): best after 20 runs 83 vs 60, median run 107 vs 61 min, so they were halved; the halved values and the 8-wave byte rhythm have not been simulated yet. Listed in the pause panel and sent with run stats (`gl`).
- Bosses: every 16 waves (2 bytes make a word: 16/32/48/64/80), always every 16, also after 96 (user's choice); moved from 20/40/60/80 + every 10 from 100 on 2026-11-04 (user's idea, bits/bytes theme; arrival also tears the screen, banner "<name> compiled!"). Every boss wave ends on a byte, so beating it is followed by a glitch pick. Not re-simulated yet. Brute, Swarm Queen (spawns Runners), Warden (shield, Blast breaks it). No escapes: a boss at the tower keeps hitting every second until it or the tower dies. Kill = 1 boss core + chips. Cores pay for Bit Theory.
- Bit Theory (research, "finding the deeper meaning in pixels"): one timed study at a time in real time (keeps running while closed), paid with cores + chips. Spray and Pray, Piercing bits, Critical bits, Blast tech, Bit depth (x1.2 damage per level, the long-term multiplier), Overclock (5 bosses; 4 levels of +0.5x game speed, own `cost`/`time` per level, levels 3-4 expensive). The speed button (top-left of the game screen, shown once Overclock is studied) cycles 1x up to the max; saved as `spd`. Speed only scales game time in `advance()`; banners, labels, zoom, shake, research, music and the cat stay real-time. Crit hits flash the enemy yellow and pop a small damage number (capped at 8 on screen). Unlocks after the first finished run; level 1 of any research costs `RES_FIRST` (10) chips and no cores, and the first Critical bits study is free (user's choice: Lv1 = 10% crit, +5% per level after, Lv10 = 55%; `critPct`), so a new player can start a 10-15 min study on day one. Researches have requirements (bosses beaten, best wave, other research levels): Critical and Piercing first, then Spray and Pray, Blast tech, Bit depth. Data in `BITS` in index.html. Game over has Restart, Foundry and Main menu.
- The run keeps going when the tab is hidden (no auto-pause; missed time is simulated on return, up to 30 min, silently). Pausing is manual: Pause opens a panel with Resume and Stop run; Stop run asks for confirmation, then ends the run like a death (saved to History as "Stopped").
- The cat (requested by my daughter): grey pixel cat drawn inside the game screen during runs, every 15-30s: peeks from the left/right edge (blinks twice) or walks along the bottom (sometimes sits). Hanging from the top was tried and removed (looked awkward). Tap = it answers with a cat word (Meow!, Mrrr, Purrr, Mrrp?, Prrrt!, Mew!) and hearts; one roll: 10% +5 HP (gold), else 30% +1 HP. It also talks by itself sometimes (*yawn* while sitting, Mrrp? when peeking). A tapped walking cat sits for a moment, then walks on. Purely decorative, never pauses. Sprites in `CAT_SPR`; she may draw her own in Piskel later.
- Audio: all sound is generated in code (no files). Background music is a quiet procedural lo-fi song (`MUSIC`, 70 BPM): 8-bar sections A/B/C/D with different chords, chained in a random musical order, varying arpeggios, soft melody and brushed percussion, on its own bus; Sound mutes everything, Music toggles only the music (saved as `music`). On iPhone the page declares `navigator.audioSession.type='playback'` so sound plays with the silent switch on (iOS 17+; pauses other apps' audio while playing), and unlocks/resumes audio on taps.
- History: every finished run is saved (last 50: date, wave, killer, chips, duration, Blasts used, record) and shown from the home menu.

## Technical rules
- Keep it a single `index.html` unless I explicitly ask to split it up. Exception (approved 2026-11-02): `server/` holds the stats backend (`stats.py`, Python stdlib + SQLite on the Droplet, nginx snippets, systemd unit; setup in `server/README.md`).
- Stats: the game sends anonymous events with `track(type,data)` (`open`, `run`, `research`, `foundry`) using the save's random `uid`; no names or IPs. Live site only (preview runs never count; the server rejects anything else). The dashboard is at /stats behind nginx basic auth. No in-game privacy note (my choice). New events need a type in `TYPES` in stats.py and a line on the dashboard.
- Pixel look: low-res internal canvas scaled up, `image-rendering: pixelated`.
- Must work on desktop and phones: touch-friendly buttons, no horizontal scroll, page padding, safe-area insets.
- Always dark theme (decided 2026-11-04): the page ignores the phone's light/dark setting, because light page chrome around the dark game screen looked bad. No light mode.
- Saved data lives in localStorage under `pixelTowerMeta`. Do not break existing saves when changing the data shape; add new fields with defaults. The save has a version `v` (`SAVE_V` in code); bump it and add a migration step in `loadMeta` when the shape changes.
- Test by opening `index.html` in a browser (`open index.html` on macOS).
- Before handing work to me, test it: run `tests/run.sh` (headless Chrome, see `tests/README.md`) and add or update tests for the change. Check the layout at phone widths with `tests/shot.sh` (390px and 320px). For balance changes, run `tests/balance.sim.js` and report the numbers.

## Git and deploy
- Repo: github.com/deivydasz/pixel-tower (private), branch `main`.
- Pushing to `main` auto-deploys to my server via a GitHub Action (`.github/workflows/deploy.yml`), so a push to `main` is a live release.
- Live site: https://idlepixeltower.duckdns.org (DigitalOcean Droplet, nginx, Let's Encrypt). The Droplet also runs a Rails app outside nginx; only touch the `pixel-tower` nginx config.
- Preview: pushing any `feature/*` branch deploys it to https://preview.idlepixeltower.duckdns.org (`.github/workflows/preview.yml`, separate saves from live, one slot = last pushed branch). After pushing a branch, check the Preview run and tell me to try it there before I say "push".
- NEVER push to `main` without asking me first. Work on a branch named like `feature/short-name` and commit there.
- Commit messages: short, imperative, one line (e.g. "Add boss wave every 10 waves").
- Release flow: push the branch, open a PR, then merge it into `main` with a merge commit (`gh pr merge --merge`, no squash or fast-forward) so every feature stays traceable in history. Then check the deploy run with `gh run watch`.
- Before asking to push, summarise what changed and how I can test it.
- When I say "push", that approves the whole release: push the branch, open a PR that explains the changes, merge it with a merge commit, then confirm the deploy run succeeded and the change is on the live site.
- `deploy.yml` looks like it only runs `ssh ... true`, but the server does the deploy on that login. A green Deploy run means the release is live; don't "fix" the workflow.
- When I need to run commands on the server, give each as a single line I can paste (multi-line heredocs break when pasted from the terminal). I'm logged in as root there.
